Cron Run History

Record every scheduled action run: status, duration, records processed and the error traceback — without access to the server log.

Odoo 20.0 Community & Enterprise AGPL-3

Highlights

Every run recorded

Start, end, duration and status of each run of each scheduled action.

Errors with traceback

A failed run keeps its error message and full traceback, although Odoo rolls back the job.

Timeouts made visible

Runs whose process stopped before the end are marked Interrupted; runs Odoo skipped after repeated timeouts are marked Timed Out.

Batch progress

Iterations, records done and records remaining for jobs that report their progress.

Scheduler or manual

Each run shows whether the scheduler started it or a user clicked Run Manually, and who.

Cleans up after itself

Runs older than 30 days are deleted automatically; the period is a system parameter.

One list for all runs

Settings › Technical › Automation › Scheduled Action Runs lists the runs, most recent first, with a coloured status badge. Filter the failed runs (failed, timed out, interrupted), partially done or running ones, the manual runs, or a period; group them by scheduled action, status, how they were started or day. Open a run to read its error and traceback.

Runs button on the scheduled action

The form of a scheduled action gets a Runs button with the number of recorded runs and the status of the last one, shown in red when it failed. A click lists the runs of that action.

How to use

  1. Install Cron Run History from Apps. Nothing to configure: the next runs are recorded.
  2. Go to Settings › Technical › Automation › Scheduled Action Runs, or open a scheduled action and click Runs.
  3. Use the Failed filter to find the runs that went wrong and open one to read the traceback.
  4. To keep runs longer or shorter than 30 days, set the system parameter cron_run_history.retention_days (developer mode, Settings › Technical › Parameters › System Parameters); 0 keeps every run.

Technical details

  • Depends on: base only.
  • New model ir.cron.run, readable and deletable by Settings administrators (Administration / Settings group).
  • Extends ir.cron by overriding _process_job, _add_progress, _callback, _update_failure_count and method_direct_trigger; the job itself runs unchanged.
  • Each run is written in short database transactions of its own, one at the start and one at the end, so a run stays visible as Running while it works and its record survives the rollback of a failed job.
  • If the history cannot be written, a warning is logged and the scheduled action runs as usual.
  • Two auto-vacuum methods: one deletes runs older than the retention period, one marks as Interrupted the runs left Running by a process that stopped.
  • Only runs that happen after the installation are recorded. Uninstalling the module deletes the history.
