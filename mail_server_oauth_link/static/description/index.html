Email · Gmail & Outlook OAuth

Mail Server OAuth Link

Send the Gmail / Outlook authorization link of a mail server to the mailbox owner instead of opening it yourself.

Odoo 19.0 Community & Enterprise AGPL-3

The problem

With Gmail or Outlook OAuth authentication, Connect your Gmail/Outlook account opens the sign-in page in the administrator's own browser. The authorization is made for the account the administrator is signed in to — the wrong mailbox when they set up sales@ or a colleague's address. Odoo gives no way to hand that sign-in to the owner of the mailbox.

Highlights

A link to send

A button next to the stock one on outgoing and incoming Gmail and Outlook servers, with a copy field.

No Odoo user needed

The owner opens the link, signs in to Google or Microsoft with the mailbox account and approves.

Right mailbox only

Odoo checks the signed-in account and logs in to the mailbox with the new authorization; if either fails, nothing is saved.

Signed, single use

Signed, bound to one server and its address, valid 24 hours by default, revocable; its secret stays out of server logs.

You are told

The administrator who made the link gets an Odoo notification when the owner has authorized the server.

Same OAuth app

The stock redirect URIs are reused: nothing new to register at Google or Microsoft.

How to use

  1. Install Mail Server OAuth Link from Apps.
  2. Go to Settings › Technical › Email › Outgoing Mail Servers (or Incoming Mail Servers), choose Gmail or Outlook OAuth Authentication and enter the mailbox address as Username.
  3. Click Get a link for the mailbox owner, copy the link (Odoo keeps no copy) and send it to the owner, who must be able to sign in to the mailbox.
  4. The owner opens it, clicks Continue with Google or Continue with Microsoft, signs in with the mailbox account and accepts.
  5. The server shows Gmail Token Valid or Outlook Token Valid. The link works once and expires; getting a new link, Revoke Link in the dialog, archiving the server or changing its address makes it stop working.

Technical details

  • Depends on: google_gmail, microsoft_outlook (both in Community, installed with Discuss).
  • Adds to ir.mail_server and fetchmail.server: the hashes of the link secrets, the link expiry and its creator (administrators only; the link itself is not stored); a dialog model mail.server.oauth.link.wizard.
  • Overrides the four stock callback routes /google_gmail/confirm, /google_gmail/iap_confirm, /microsoft_outlook/confirm and /microsoft_outlook/iap_confirm: they accept visitors without a session for owner links only; any other request still goes to the login page.
  • The link opens /mail_server_oauth_link/authorize with its secret in the URL fragment (never sent to a server); the page keeps it in an HttpOnly cookie. The OAuth state carries a separate one-time value valid one hour at most.
  • Account check: Gmail from Google's user info (the stock userinfo.email scope); Outlook from the id token of a server-side token refresh, like the stock check. No scope is added. Then Odoo logs in to the mailbox with the new tokens (SMTP MAIL FROM / RCPT TO without sending, or IMAP login) before keeping them.
  • Without own client ID and secret, Odoo Enterprise uses Odoo's IAP proxy and the owner link follows it; on Community the client ID and secret are required, as for the stock button.
  • The link is valid 24 hours; system parameter mail_server_oauth_link.validity_hours changes it (1–168). The owner page needs JavaScript.
  • Uninstall removes the added fields and the dialog; the saved tokens stay on the servers.
